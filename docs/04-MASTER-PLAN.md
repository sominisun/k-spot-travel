## 3. 수익 사다리 — 무료는 넓게, 소액은 가볍게, 구독은 팬답게

### 3.1 3단 구조

```
[FREE]  전 콘텐츠 열람 + 플래너 "요약판"
          일자별 테마 + 스팟 목록 + 지도 미리보기 — 가치를 충분히 증명
   ↓  "이 일정, 분 단위 동선으로 받아볼래요?"
[PASS]  루트 패스 — $4.9 단건
          시간대별 동선 + 식당 예약 타이밍 캘린더 + 지도 딥링크 묶음
          + PDF & .ics(캘린더 파일) + 30일 내 재생성 3회
   ↓  "매 분기 신작 드롭을 가장 먼저"
[INSIDER]  K-SPOT Insider — $3.9/월 · $29/년
          플래너 무제한 + 신작 촬영지 드롭 D+7 우선 공개
          + Insider 뉴스레터(월 2회) + Discord 전용 채널 롤
          + 시즌별 짐싸기/예약 체크리스트 + 위시리스트·플랜 클라우드 저장
```

**왜 이 구조인가**: 무료층이 SEO·AdSense·제휴를 돌리는 본체이고(A안 계승), 유료는 "정보"가 아니라 **"내 것으로 만들어주는 수고"**를 팝니다. 정보를 잠그면 팬덤이 등을 돌리지만, 개인화를 팔면 고마워합니다. 그리고 전부 AI+자동화 산출물이라 **구독자 1,000명이 되어도 운영자의 손은 늘지 않습니다.**

### 3.2 결제 인프라 (1인 운영 기준 확정)

- **Lemon Squeezy** 채택 (Stripe 대안 비교 후): Merchant of Record라 **전 세계 부가세/판매세를 대신 처리** — 글로벌 소액결제를 1인이 굴릴 때 세무가 최대 리스크인데 이를 구조적으로 제거. 단건+구독+환불 대시보드 일체형, 체크아웃 오버레이 삽입 코드 몇 줄
- 인증: 비밀번호 없는 **이메일 매직링크** — 결제 이메일 = 계정. 가입 마찰 최소
- 게이팅: 웹훅 → 구독 상태 저장(Upstash Redis 무료 티어) → 플래너/드롭 페이지에서 상태 확인
- 환불 정책 페이지, 결제 페이지 광고 미노출(AdSense 정책·전환 보호)
- B단계 확장 시: 같은 인프라 위에 컨설팅·패키지 상품만 추가하면 됨 (A→B 심리스 유지)

| # | 장치 | 작동 방식 | 왜 후킹되나 |
|---|---|---|---|
| 1 | **"다음 여행지 테스트"** 퀴즈 | 8문항 성향 테스트 → "당신의 다음 여행은 『폭싹 속았수다』의 제주" + 공유 카드 | K-팬덤은 성향 테스트 공유 문화의 본진. 결과가 곧 작품 허브 유입 |
| 2 | **성지순례 스탬프** | 스팟 페이지 "다녀왔어요" 체크 → 작품별 스탬프 카드 채워짐 → 완주 시 공유용 인증 카드 생성 | 수집욕 + 인증욕. 여행 후에도 사이트로 돌아올 이유 |
| 3 | **주간 드롭** | 매주 1회 신작/재조명 촬영지 가이드 발행 — 뉴스레터·Discord 동시 핑. Insider는 D+7 선공개 | "이 사이트는 살아있다"는 감각. 구독 전환 지점 |
| 4 | **플랜 공유 카드** | 플래너 결과 → 슬로건 박힌 이미지 카드(OG 자동 생성) → SNS·Discord 공유 | 사용자가 만든 결과물이 곧 광고 |
| 5 | **Fan Frame** | Discord #spot-photos 인증샷 중 월간 선정 → 홈 "이달의 팬 프레임" 게재(동의+크레딧) | UGC가 콘텐츠가 되는 순환. 선정된 팬은 평생 홍보대사 |
| 6 | **뉴스레터 "The K Edit Weekly"** | 주간 드롭 + 지금 서울 이벤트 + 이달의 팬 프레임 요약 | 이메일 리스트 = 알고리즘에 휘둘리지 않는 자산 |

운영 부담 합계: 주간 드롭은 기존 "신작 1편/주" 루틴과 동일 작업, 나머지는 자동/월 1회.

## 5. 챗봇 — 묻고 끝나는 창이 아니라, 사이트를 성장시키는 귀

### 5.1 Q&A 로그 구조 (복잡하지 않게, 그러나 빠짐없이)

```
사용자 질문
   ├→ ① 즉답 (Claude 또는 FAQ/검색 폴백) — 질문 언어로 답변
   ├→ ② 전 문답 로그 저장 (Upstash Redis: 질문·답변·언어·페이지·만족 여부)
   └→ ③ 답변 실패/저신뢰 시 → Discord 웹훅으로 운영자 개인 채널 #chat-inbox에 즉시 전송
          → 운영자는 폰 알림으로 실시간 확인 (별도 관리자 페이지 불필요!)
```

- 답변 하단 "도움이 됐나요? 👍👎" — 👎는 자동으로 인박스행
- "에디터에게 직접 물어보기" 버튼: 이메일(선택) 남기면 운영자가 후속 답변 → 서비스가 아니라 **팬 대응**으로 체감됨
- **주간 15분 FAQ 루프**: 인박스에서 반복 질문 확인 → `faq.ts`에 3~5개 추가 → 챗봇이 다음부터 즉답 + 같은 주제로 가이드 아티클 기획. **사용자의 질문이 콘텐츠 로드맵이 되는 구조** — 이것이 "신속 대응"의 실체이자 1인 운영의 정답

### 5.2 프라이버시

로그는 익명(세션 ID만), 이메일은 사용자가 직접 남긴 경우만 저장 — 개인정보처리방침에 명시.

## 6. 리텐션 루프 — "다시 오고 싶은"의 설계도

        ↓                      (지도 딥링크·예약법)                ↓

  플래너 → 패스 구매                                     Discord 정착 → 다음 작품 정주행

## 7. 실속 3장치 — "알차다"는 평판의 구조화

1. **마지막 확인일 라벨**: 모든 스팟·식당·가이드에 "Last verified: 2026-07" 자동 표기 — 여행 정보의 신뢰는 신선도에서 나옴. 분기별 재검증 루틴(스팟 30분×4회/년)과 세트
2. **"정보가 바뀌었나요?" 제보 버튼**: 모든 상세 페이지 하단 → Discord 웹훅 인박스 → 수정 후 확인일 갱신. 사용자가 품질관리에 참여 = 신뢰 + 애착
3. **검증 정책 공개 페이지**(/about 내): "우리는 공식·언론 출처로 확인된 촬영지만 싣습니다. 스틸컷을 쓰지 않는 이유, 출처를 다는 이유" — 편집 원칙의 공개가 곧 차별화 마케팅
